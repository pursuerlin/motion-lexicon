# Motion Lexicon 项目审查

审查日期：2026-10-11。范围：当前工作区的页面、样式、数据、演示引擎、框架代码生成、搜索、配方、国际化和发布流程。此次只新增审查报告，没有修改现有实现。

## 核心判断

项目最有价值的资产是「看效果 → 知道怎么称呼 → 写成需求 → 复制实现」这条链路。暖纸色、衬线标题、仪表式舞台也已经形成可保留的视觉方向。

目前优先级最高的是链路的一致性：演示、文字描述、参数和代码并不总是表达同一个动效。其次是检索入口过深、手机工具栏及菜单不可用、全量初始化与全局依赖带来的维护成本。继续增加术语数量，会放大这些问题。

## 优先修复的问题

### 1. [P1] 实验室的合法 CSS 缓动被误判

位置：`assets/lab.js:164`、`:216`。

复现：选择 linear，CSS transition 输出 `transition: transform 1200ms /* linear 无法用 CSS 曲线表达，需 JS 驱动 */;`。这段 CSS 没有指定 linear，采用默认 ease，与预览不一致。`steps(6)` 和非贝塞尔的合法曲线也走同一分支。

原因：把「曲线控制点能否拖动」当成「是否可用于 CSS easing」。

修复：分别建模 `canEditBezier`、`cssEasing`、`sampledFunction`；合法 CSS 关键字和函数直接导出。不能直接表达的曲线提供采样或明确标记不可导出，不能用注释悄悄替换。

补充：现代 CSS `linear()` 可用分段采样近似复杂曲线，所以“弹性/弹跳必须用 JS”应增加条件说明。依据：[MDN linear()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/easing-function/linear)。

### 2. [P1] 框架转换不保证语法与动效等价

位置：`assets/dialects.js:276`、`:321`、`:341`、`:373`；`assets/lab.js:187`。

已观察到的输出：

- slide-in：源是 `translateX(46px) → 0`，Swift 输出初始 `-46 → 0`，方向反了。
- linear：Framer 输出固定 `[0.16, 1, 0.3, 1]`，匀速变成 expo-out。
- rotate：Compose 输出只有 alpha，没有 rotation；Tailwind 输出也没有旋转。
- 选择 Swift/Compose 的 linear 仍返回 `animation: spin 1.2s linear infinite;`，是 CSS。
- Compose 输出先引用局部 `spec` 再声明它；scale 输出 `scaleX = scaleY = sc`，不符合 Kotlin 赋值表达方式。
- 实验室 Framer 输出 `motion.div` 开头，缺少 JSX 的 `<`。
- Tailwind 转换用绝对值并按预设刻度折算位移，会丢失符号和精确距离。例如 `-50 → 50` 被变成正向固定刻度到 0。
- Swift/Compose 多关键帧回退到 `term.code`，且能力判断仅看 `specOf(term)` 是否存在，无法说明选中的语言究竟支持什么。

修复：按“术语 × 输出平台”声明 `native / approximate / unavailable / handwritten`，把近似差异明确展示在代码旁；禁用不可导出的平台。使用统一时间轴，保留 from/to、每帧偏移、完整 transform、easing、loop、stagger。生成器不要默默吞错再返回另一种语言。

建议验收样例：入场/退场方向、只有 Y 位移、正负位移、旋转、多轴缩放、首尾相同的多关键帧、linear/steps、自定义贝塞尔、loop/alternate、stagger、spring。按平台做语法验证与抽样运行对照，而不是只检查生成器本身能否解析。

### 3. [P1] 演示调参没有同步代码和需求描述

位置：`assets/app.js:160`、`:290`、`:1078`；`assets/dialects.js:401`。

复现：滑入详情的时长从 480ms 调到 1600ms，舞台参数显示 1600ms，而代码仍是 `animation: … 0.48s …`。描述 `say` 又写 300ms。三种输出各自取不同值。

原因：演示从 `stage._prm` 读值，生成器从静态 `term.demo` 读值，缓存键只有 id 与语言；配方只拼接静态 `t.say`。

修复：使用同一个 `MotionSpec + parameterOverrides` 生成舞台、代码和提示词。缓存键包含有效参数或采用失效机制。提供“恢复默认”和“复制当前设置”，说明参数单位与范围。

### 4. [P1] 手机下拉菜单被工具栏裁切

位置：`assets/styles.css:2419`、`:2426`。

复现：390px 屏幕 `.top-tools` 宽 362px、可滚动内容宽 423px；配方按钮位于右侧不可见区域。点击主题后，菜单只露出约一行，其余内容被工具栏裁切。

原因：父容器 `overflow-x:auto` 导致纵向也成为 `auto`，绝对定位菜单被滚动容器裁切。

另外，约 493px 布局中“代码写法”“动效开”“遥测开”“配方”文字被挤成竖排，480px 的处理覆盖范围过窄。

修复：手机保留搜索与主要动作，把主题、语言、遥测等收进设置入口；菜单移到不受 overflow 限制的独立层，或用合适的原生弹出层。定义 390/480/493/768/1024px 等关键宽度验收。触控动作保持至少约 44px，避免隐藏横向滚动承担主要功能。

### 5. [P1] 不可见菜单可获得键盘焦点，详情背景仍暴露

位置：`assets/styles.css:168`；`assets/app.js:456`、`:1190`。

复现：关闭代码菜单时，在菜单触发按钮按 Tab，焦点进入不可见的 CSS 选项，菜单仍是关闭状态。使用 opacity 与 pointer-events 隐藏，并不会移出 Tab 序列。

详情显示时，背后的主页仍是 `display:block`、`visibility:visible`，可访问性树也仍包含主页。移动焦点到详情容器不能替代背景隔离。

修复：关闭菜单使用 hidden/inert 或同步 tabindex；完善打开、方向键、Esc、焦点回收。覆盖式详情启用背景 inert 并处理焦点边界，或者改成真正独立的路由页面。卡片是 `article role=button`，内部又包含滑块和按钮，建议把“打开详情”和“操作演示”拆成不同交互目标。

### 6. [P2] 搜索后的结果离入口太远

位置：`index.html:68`、`:90`；`assets/app.js:1013`、`:1019`。

桌面首屏里，术语区域起点约为页面 1310px。输入“弹”命中 29 条后，介绍与实验室仍占据原空间，用户只能看到顶部计数变化。

当前搜索是整串 `indexOf` 匹配，没有字段权重、多个关键词拆分、结果相关性排序；索引含中文正文和英文名称，但不含英文翻译正文。分类和收藏可叠加，缺少集中可见的筛选条件与“重置全部”。

修复：首屏直接提供术语入口与示例查询；开始搜索时显示结果工作区。给名称、别名、定义不同权重，支持多个关键词和输入纠错，标记命中位置。空结果提供清除分类/收藏过滤与相近词。语言切换后仍保证对应语言内容能被检索。

### 7. [P2] 内容承诺、数量、术语层级不一致

位置：`README.md:5`、`index.html:8`、`:73`、`:88`；`assets/compound.js:31`。

README 是 239，页面 meta 是 242，运行时是 244。引言承诺“每个词…七种框架的可运行代码”，实际不支持的条目会回退或只提供片段。当前的运行时分组和组合范式，也已超出引言列出的七种分类轴。

修复：计数从数据生成；把文案改为真实的覆盖范围。区分标准术语、工程/API 概念、设计建议和本站命名的组合模式；例如“悬停触发车门绽放”可以作为组合案例命名，但应说明它的组成词，而不是让读者误认为是统一行业术语。

内容模型补齐：适用场景、慎用场景、触发方式、组成概念、来源、最后核验时间、平台支持范围、实现精度。规范性建议与事实分开标注，避免把“默认优选”写成绝对规则。

### 8. [P2] 配方仍是句子拼接，无法表达完整编排

位置：`assets/app.js:1078`；`assets/i18n.js:34`、`:66`。

当前按加入顺序拼接 `say`，不表达作用对象、触发器、前后顺序或并行关系；调整过的参数也不带入。中文与英文的通用约束存在强弱差异：英文要求只动 transform/opacity，但部分所选概念本身需要 mask、clip-path、SVG stroke 等。

修复：配方存为结构化 steps：target、trigger、effect、parameters、start/after/parallel、reducedMotionFallback。允许拖动排序、分组和保存。输出约束应根据实际所选动效生成，性能优选与必须满足的限制明确区分。

### 9. [P2] 本地化和发布门禁尚未闭环

自检失败的词条：

- `assets/motion.js:765`：同一数值变化：1111 到 8888。
- `index.html:180`：本站借鉴部分动效概念并独立实现；插画与完整作品未直接搬运。
- `assets/compound.js:807`：音乐实时活动示例。

`termMarkdown()` 仍直接读取中文原文和中文标题，因此英文界面导出仍混有中文。当前本地化以中文文案本身作为 key，修改文案容易导致映射失效。

`.github/workflows/pages.yml` 直接上传部署，没有运行 `check.sh`。现有自检不覆盖生成代码、动效等价性、数据 schema、浏览器交互和动态翻译缺失。

修复：稳定的 i18n key；翻译与内容 ID 对齐；部署前运行自检与必要的交互/导出检查。`check.sh` 实际是 Python，建议更名 `check.py` 并更新文档。

## 视觉与信息架构建议

保留暖纸底、衬线标题、橙色强调和仪表语言。优先调整比例和层级：

1. 顶栏让搜索成为主角；语言、主题、减弱动效、遥测集中到设置。代码平台选择放到代码区域，降低新用户进入时的决策量。
2. 首页缩短介绍，加入明确的“浏览术语”“按场景找动效”“生成需求”入口。统计数字退为辅助信息。
3. 缓动实验室改为独立工具入口或可收起区，术语图鉴前置；已有使用习惯可通过入口位置和状态记忆保留。
4. 浏览卡片显示：一段清楚的演示、中文主标题、英文副标题、一句话用途、触发方式标签。高级参数和遥测按需展开。
5. 详情页建立“适用场景 → 演示调参 → 描述/提示词 → 代码 → 注意事项/来源”顺序。简单淡入不必占与三维场景相同的大舞台。
6. 基础术语、组合案例、实验室和收藏配方分成清晰的一级入口；分类继续作为内容过滤维度。按“按钮反馈、列表入场、页面转场、滚动叙事、数字变化”等场景提供第二条发现路径。
7. 小字号参数和控件文字以可读性为先，增加对齐与留白的一致性。统一普通按钮、图标按钮、chip、tab、菜单的高度和状态，减少不同区域分别覆盖样式。

## 扩展性改造方向

当前纯静态方案适合部署，暂时没有证据要求整体迁移到 React 或引入服务端。先明确模块边界：

```text
content/      分类、词条、双语正文、来源、关联内容
spec/         MotionSpec、参数定义、能力声明、数据校验
engine/       调度器、可见性、减弱动效、资源释放
demos/        按演示类型注册的 mount/update/destroy
exporters/    按平台生成代码及能力状态
features/     搜索、收藏、配方、路由、实验室
styles/       token、基础控件、页面布局、舞台专用样式
```

关键原则：

- 内容、演示与输出共享规格，避免三个实现各自修复。
- 将 runtime/compound 中“向 window.TERMS 推数据”和“注册演示实现”分开。用 ES modules 显式导入替代脚本顺序和 window 全局耦合；类型可用 TypeScript 或 JSDoc 增量加入。
- 每种演示有 mount/update/destroy 契约，统一管理 rAF、事件、ResizeObserver、WebGL/Canvas 资源。
- 索引卡片先渲染名称/预览，接近视口时再挂载复杂舞台，详情按需加载。现有离屏暂停保留。5914 个 DOM 元素和全量 mount 是成本证据，但尚未实测 LCP/INP/低端设备耗时，不应直接宣布“性能不合格”。
- token 和组件规则集中维护；清理重复断点与覆盖，舞台样式独立，避免 3851 行主 CSS 随内容继续膨胀。
- 保持稳定词条 ID。增加内容唯一性、分类引用、翻译完整性、demo/参数合法性、平台能力与来源 URL 校验。
- 词条已有 `#term/id` 深链接，但内容全部依赖客户端生成。若需要搜索引擎收录与逐条分享卡片，再增加静态预渲染、独立 URL、sitemap 和每条 meta。

## 实施顺序与验收

### 第一轮：准确、可用

修复实验室合法缓动、各语言输出能力及回退、演示与输出参数一致；修手机菜单裁切和窄屏工具栏；修不可见菜单焦点；补翻译并把自检接进发布。

验收：linear/steps 正确导出；滑入方向和时长与演示一致；不支持的平台明确禁用；390/493/768px 菜单完整可见；关闭菜单不能 Tab 进入；发布检查失败时不部署。

### 第二轮：更好看、更容易找

前置术语列表、压缩引言、实验室独立入口；搜索相关性、场景发现、筛选提示；调整卡片和详情层级、精简默认遥测。

验收：用户从首页能立即到达术语；输入关键词后能在当前工作区看到结果；手机主要操作无需找隐藏横向滚动；简单/复杂舞台有合适比例。

### 第三轮：更容易扩展

数据模型和模块边界、懒挂载、统一生命周期、结构化配方、来源与版本、静态预渲染（按传播需求决定）。

验收：新增词条只需内容数据与已有演示规格；新增 demo 或输出平台按契约注册；删除/重开详情不会残留资源；配方能明确表达对象、参数和编排并复现。

建议用 Impeccable harden/adapt/clarify 处理第一轮，layout/typeset 处理第二轮，最后 polish。动效词典的教学展示应保留，机械检测器的风格告警必须逐条判断。
